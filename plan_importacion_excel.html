FEATURE 4

Importación masiva de servicios desde Excel

CEM BackEnd — Express / TypeScript / Sequelize Dependencias: xlsx (SheetJS) · multer Fecha plan: 2026-06-03

Contexto y objetivo

El proveedor puede crear sus servicios/productos uno por uno desde la UI, pero cuando tiene un catálogo de decenas de ítems, el proceso manual es lento. Esta feature permite subir un archivo .xlsx con toda su tienda de una vez.

Qué hace el proveedor

  1. Descarga la plantilla Excel desde CEM
  2. Rellena sus productos con precios base
  3. Sube el archivo → obtiene un preview
  4. Confirma → los productos se crean en su tienda
  5. Agrega imágenes manualmente después

Qué hace el sistema

  1. Parsea el Excel con SheetJS
  2. Valida cada fila (tipo, enum, requeridos)
  3. Calcula el precio público con la comisión del contrato
  4. Devuelve preview con errores por fila
  5. En confirmar: bulkCreate solo las filas válidas

Cálculo de precio — regla central

precio_público = precio_base × (1 + comisión_cliente / 100)
precio_base = lo que el proveedor quiere recibir (viene del Excel)
comisión_cliente = Contrato.comision_cliente_porcentaje del contrato vigente del proveedor (Feature 1, inmutable)
precio (columna existente en ServiciosAdicionales) = precio_público = lo que ve el cliente
⚠ El precio público nunca se lee del Excel — siempre se recalcula desde el contrato. Si el Excel tuviese una columna "precio_publico", se ignora. Esto previene que un proveedor manipule precios eludiendo la comisión.
✓ contratoVigenteRequired ya está disponible y se aplica a estos endpoints — si el proveedor no tiene contrato vigente, no puede importar. La comisión está garantizada de existir cuando llega al controller.

Formato del Excel — columnas esperadas

La primera fila debe ser el encabezado. Los nombres de columna son insensibles a mayúsculas y espacios (se normalizan al parsear).

ColumnaTipoOblig.Valores válidos / notas
nombre texto ✦ Requerido Máx. 255 chars. No puede estar vacío.
descripcion texto Opcional Máx. 500 chars. Default vacío.
precio_base número ✦ Requerido Positivo, sin símbolo $. Lo que recibe el proveedor.
categoria enum ✦ Requerido catering · decoracion · audio_video · seguridad · mobiliario · entretenimiento · otro
tipo_precio enum Opcional fijo (default) · por_persona · por_hora · por_turno
tipo_item enum Opcional producto (default) · servicio
presentacion texto Opcional Texto libre (ej: "bandeja x12"). Se concatena al final de descripcion. No requiere columna nueva en DB.

ℹ Las imágenes no van en el Excel. El campo imagen se crea como null y el proveedor la sube después desde la UI, como ya lo hace hoy con PUT /api/servicios/mis-servicios/:id.

Campo nuevo: precio_base en ServiciosAdicionales

El modelo actual solo tiene precio (precio público). Para preservar el precio base del proveedor necesitamos una columna nueva.

Migración SQL

Archivo: 20260603_add_precio_base_servicios.sql

NULL permite que servicios creados manualmente (sin import) no tengan precio_base. En esos casos, el precio base = precio público (sin markup).

Endpoints

GET /api/servicios/plantilla-excel Descargar plantilla

authRequired

Genera un .xlsx con los encabezados correctos y 2 filas de ejemplo. Devuelve con Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet y Content-Disposition: attachment; filename="plantilla_servicios.xlsx". El proveedor la descarga, la rellena y vuelve.

POST /api/servicios/importar-excel/preview Parsear sin guardar

authRequired contratoVigenteRequired multer.single('archivo')

Recibe el archivo, parsea todas las filas, valida y calcula precios públicos. No guarda nada. Devuelve:

{
  "comision_aplicada": 10,          // % del contrato
  "filas_validas": [ { "fila": 2, "nombre": "Catering Premium",
    "precio_base": 80000, "precio": 88000, "categoria": "catering", ... } ],
  "filas_invalidas": [ { "fila": 5, "error": "precio_base inválido" } ],
  "total_validas": 8,
  "total_invalidas": 1
}

El frontend muestra este resultado para que el proveedor revise antes de confirmar.

POST /api/servicios/importar-excel/confirmar Guardar servicios válidos

authRequired contratoVigenteRequired multer.single('archivo')

Mismo parseo + validación que preview, pero al final hace ServicioAdicional.bulkCreate() con las filas válidas. Las filas con error se reportan pero no abortan la importación. Devuelve:

{
  "ok": true,
  "creados": 8,
  "errores": [ { "fila": 5, "error": "precio_base inválido" } ]
}

Flujo completo paso a paso

1

Proveedor descarga plantilla

GET /api/servicios/plantilla-excel → SheetJS genera .xlsx en memoria → browser descarga el archivo

2

Proveedor completa el Excel

Rellena columnas: nombre, descripcion, precio_base, categoria, tipo_precio, tipo_item, presentacion, capacidad_maxima. No pone imágenes ni precio público.

3

Upload para preview

POST /api/servicios/importar-excel/preview con el archivo en multipart/form-data campo archivo. Multer valida MIME y tamaño (máx 5MB). Controller parsea con SheetJS (XLSX.read(req.file.buffer)), normaliza headers, valida cada fila y calcula precios. Ninguna escritura en DB.

4

Frontend muestra preview

Tabla con filas válidas (nombre + precio_base + precio_público calculado + errores si hay). El proveedor puede corregir el Excel y volver al paso 3, o confirmar.

5

Confirmación

POST /api/servicios/importar-excel/confirmar — mismo archivo subido de nuevo. Re-parsea (stateless), hace bulkCreate de las filas válidas con proveedor_id del usuario logueado. Responde con count de creados y lista de errores (si los hay).

6

Post-importación

Servicios creados con disponible: true, imagen: null. El proveedor va a su tiendita, entra a cada item y sube imagen desde el formulario de edición existente.

Extractos de implementación

uploadExcel.ts — middleware multer

import multer from 'multer'

const MIMES_VALIDOS = new Set([
  'application/vnd.openxmlformats-officedocument.spreadsheetml.sheet', // .xlsx
  'application/vnd.ms-excel',                                          // .xls
  'application/octet-stream',                                           // algunos navegadores
])

const uploadExcel = multer({
  storage: multer.memoryStorage(),
  limits:  { fileSize: 5 * 1024 * 1024 }, // 5 MB
  fileFilter: (_req, file, cb) => {
    MIMES_VALIDOS.has(file.mimetype)
      ? cb(null, true)
      : cb(new Error('Solo se permiten archivos .xlsx o .xls'))
  }
})

export default uploadExcel

parseo de filas — normalización de headers

import * as XLSX from 'xlsx'

function parsearExcel(buffer: Buffer): Record<string, any>[] {
  const wb  = XLSX.read(buffer, { type: 'buffer' })
  const ws  = wb.Sheets[wb.SheetNames[0]]
  const raw = XLSX.utils.sheet_to_json<any>(ws, { defval: '' })
  // Normalizar claves: minúsculas sin espacios
  return raw.map(r =>
    Object.fromEntries(
      Object.entries(r).map(([k, v]) => [k.trim().toLowerCase().replace(/\s+/g, '_'), v])
    )
  )
}

function precioPublico(precio_base: number, comisionPct: number): number {
  return +(precio_base * (1 + comisionPct / 100)).toFixed(2)
}

Decisiones de diseño y consideraciones

Stateless preview → confirmar

El archivo se sube dos veces. No hay sesión ni cache de estado entre preview y confirmar. Esto evita tener que gestionar tokens temporales, expiración de sesiones de importación, o storage de archivos. El parse es instantáneo (<50ms para 1000 filas).

memoryStorage en multer

El archivo no se escribe a disco. Vive en req.file.buffer solo durante el request. SheetJS puede parsear desde Buffer directamente con XLSX.read(buffer, { type: 'buffer' }). Sin archivos temporales que limpiar.

precio_base nullable

Los servicios creados manualmente (flujo existente) no tienen precio_base. Solo los importados lo tienen. Esto no rompe nada existente — la UI actual puede ignorar el campo.

presentacion → descripcion

"bandeja x12" se concatena como "Buffet frío (bandeja x12)" en descripcion. Evita agregar otra columna al modelo. Puede extraerse visualmente en el frontend si se necesita.

⚠
MIME spoofing: Un usuario malintencionado puede subir un archivo .html renombrado a .xlsx. La validación por MIME (Content-Type) que manda el browser no es suficiente. SheetJS tirará una excepción al intentar parsear un archivo no-Excel — el try/catch lo maneja y devuelve HTTP 400 con "Archivo Excel inválido o corrupto". Eso es suficiente para este caso.
